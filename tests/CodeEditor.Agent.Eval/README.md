# Бенчмарк агента

Агент без окна решает задачи на маленьких репозиториях из `Fixtures`:

- `Calc` — библиотека-калькулятор и её тесты, 14 задач попроще;
- `Shop` — бэкенд магазина из трёх проектов с правилами в `AGENTS.md`, 3 сложные задачи.

После хода прогон проверяет результат:

- ответ на вопрос;
- скрытые тесты из `Hidden`;
- чистую сборку и зелёные тесты;
- неприкосновенные файлы и запрещённый текст.

Итог — таблица «модель × режим»:

- доля решённых задач;
- балл — средняя доля пройденных скрытых тестов: показывает, насколько близко агент подошёл, даже без полного решения;
- сколько тестов агент добавил;
- запросы, вызовы инструментов, токены, время и стоимость.

## Запуск

Прогон тратит токены: 6 задач × 3 режима — это десятки запросов к модели. Ключ берётся из редактора (хранилище
пользователя, только чтение) или из переменной `CODEEDITOR_AGENT_KEY`.

```bash
dotnet run --project tests/CodeEditor.Agent.Eval -- --models openai/gpt-6-luna --modes agent
```

Параметры:

- `--models a/b,c/d` — модели через запятую (по умолчанию модель агента по умолчанию);
- `--modes agent,deep,ask,plan` — режимы (по умолчанию `agent`; до ADR 0010 были `light`, `medium`, `power` — они читаются как `agent`). `deep` — «Глубокий» с советником (ADR 0012): дороже, советник и ревьюер — отдельные запросы;
- `--advisor-model vendor/model` — модель советника и ревьюера режима `deep` (по умолчанию — модель агента). Сравнивать стоит пары: `agent` на модели исполнителя, `agent` на модели советника и `deep` с советником — только так видно, дал ли режим что-то сверх лучшей из моделей;
- `--tasks find,fix-divide` — задачи, по умолчанию все:
  - на `Calc`: `find`, `fix-divide`, `failing-test`, `negative-numbers`, `add-power`, `rename-sub`, `add-mod`,
    `culture-bug`, `switch-fix`, `extract-number`, `precedence`, `expressions`, `two-bugs`, `invalid-input`, `overview`
    и `web-search` (их ответы оцениваются вручную; `web-search` — вопрос, ответа на который нет в репозитории: проверка поиска в
    интернете, ADR 0025). `switch-fix` — два запроса одного чата: «в чём причина?» в режиме «Вопрос», затем
    режим меняется на режим прогона и уходит «внеси эту правку»; в `results.json` — время второго запроса
    (`FollowUpElapsed`);
  - на `Shop`:
    - `shop-promo` — промокоды по спецификации с крайними случаями;
    - `shop-penny` — копейка в письме по симптому;
    - `shop-stock` — две связанные ошибки склада по симптому;
- `--runs 3` — повторы каждой пары, чтобы сгладить случайность модели;
- `--timeout 600` — предел на задачу в секундах;
- режим `cursor` (`--modes cursor`) — вместо нашего агента задачу решает Cursor CLI (`cursor-agent`, нужен вход
  `cursor-agent login`) в той же копии репозитория, с тем же запросом и той же проверкой; модель Cursor —
  `--cursor-model grok-4.7-xhigh-fast` (список — `cursor-agent models`), `--models` задаёт модель ProxyAPI, по цене
  которой считаются токены Cursor. Поток событий — `cursor.jsonl` в папке прогона. Предел расхода на задачу к
  Cursor не применяется (расход он сообщает только в конце хода);
- `--show-prompt папка` — без модели: системный промпт и инструменты (описания и схемы параметров), которые получит модель из `--models` в режиме из `--modes` для этой папки, — JSON в стандартный вывод;
- `--reasoning high` — глубина рассуждений агента (`low`, `medium`, `high`), как настройка `agent.reasoningEffort`;
- `--ui-language en` — язык интерфейса редактора (тексты обвязки), как настройка `workbench.language`: проверить интерфейс на одном языке и запросы на другом;
- `--external папка,папка` — задачи на настоящих репозиториях: в папке `task.json` (id, `sourceRepo` — git-репозиторий,
  с которого делается клон без удалённых, файл запроса, скрытые тесты и куда их положить, тестовый проект) —
  проверяются сборка тестового проекта и только скрытые тесты;
- `--max-task-cost 20` — предел расхода на задачу в ₽ по `ModelPrice`: ход останавливается, результат — «превышен
  предел расхода на задачу»; нужен, когда модели гоняют параллельно под общий бюджет;
- `--budget 100` — предел расхода на весь прогон в ₽: следующая задача не начинается, если потраченное плюс
  `--max-task-cost` больше бюджета, отчёт пишется по сделанному;
- `--endpoint URL` — адрес OpenAI-совместимого API; по нему — ключ сервиса, цены (`ModelPrice`: ProxyAPI, Provod и AITUNNEL; у AITUNNEL
  запись в кэш Claude и GPT-6 — ×1,25 цены ввода) и колонка «Сервис» в отчёте;
- `--trace` — журнал обмена с моделью (`agent.trafficLog`): тела запросов и ответы как есть, без заголовков, — в `user/logs/model-traffic` папки задачи;
- `--pause 360` — пауза в секундах перед вторым сообщением задачи с продолжением (`switch-fix`): проверка кэша после
  простоя, например прогрева на час (ADR 0022); пауза входит во время хода — `--timeout` нужен больше;
- `--api ChatCompletions` — протокол API (`Responses`, `ChatCompletions`), как настройка `agent.api`; по умолчанию — по модели;
- `--dry-run` — без модели: заглушка отвечает «готово», проверяется только обвязка;
- `--report папка,папка` — без прогона: общий отчёт по `results.json` прошлых прогонов (например, двух моделей,
  запущенных параллельно);
- `--recheck папка,папка` — без модели: заново проверяет репозитории прошлых прогонов после исправления скрытых
  тестов или проверок и пересчитывает итог, балл и добавленные тесты. Прежние результаты остаются в
  `results.before-recheck.json`.

Отчёт `report.md` и папки прогонов (репозиторий после хода и история чата в `.breeze/agent`) — в
`%TEMP%\CodeEditor.Eval\<дата>`.

## Как добавить задачу

Задача — запись в `EvalTasks.cs` (Calc) или `ShopTasks.cs` (Shop). В ней задаются:

- запрос пользователя;
- репозиторий (`Fixture`);
- замены в чистом репозитории — ошибка задачи;
- скрытые тесты;
- неприкосновенные файлы или запрещённый текст.

Эталон в `Fixtures/<имя>` должен оставаться «зелёным». Файлы проектов хранятся с суффиксом `.fixture`, чтобы в самом
CodeEditor их не принимали за проекты решения. Тестовый проект репозитория — `tests/<имя>.Tests`.

Новую задачу проверь дважды:

- пробный прогон `--dry-run` — на исходном коде скрытые тесты должны падать;
- эталонное решение — на нём они должны проходить.

Для задач «Магазина» это сделано: на исходном коде «копейка» и «склад» набирают по 25 %, промокоды — 0 %; с исправлением
и эталонным решением промокодов проходят все тесты.
