# Безопасность

## Поддерживаемые версии

Breeze пока выходит предварительными версиями. Исправления безопасности попадают только в следующую версию.
Установленная программа получает её сама, если не отключить проверку настройкой `"update.mode": "manual"`.

| Версия | Исправления безопасности |
| --- | --- |
| Последняя опубликованная | да |
| Более ранние | нет, обновитесь |

## Как сообщить об уязвимости

Не создавайте для уязвимости открытую задачу. Сообщите о ней закрыто:
**Security → Report a vulnerability** на странице репозитория (GitHub Private Vulnerability Reporting).

Опишите, что можно сделать и при каких условиях, и приложите шаги воспроизведения. Укажите версию из
«Справка → О программе». Ответ придёт в течение недели. После исправления уязвимость будет описана в заметках к
выпуску, а автор отчёта — упомянут, если он не против.

## Что важно для Breeze

- **API-ключ** сервиса моделей хранится зашифрованным для учётной записи Windows (DPAPI) в папке
  `%LocalAppData%\Breeze\secrets` и не попадает в настройки, журналы и чаты.
- **Действия агента.** Агент запускает команды, правит файлы, открывает сайты и работает с Git и Docker. Опасные
  действия выполняются только после подтверждения пользователя. Обход этих подтверждений — уязвимость.
- **Чужие папки.** Правила (`.breeze/agent.md`, `AGENTS.md`, `CLAUDE.md`, `.breeze/rules`) и инструменты
  (`.breeze/tools`) открытой папки влияют на агента. Новый или изменённый инструмент запускается только после
  подтверждения. Если он запустился без него — это уязвимость.
- **Обновления** загружаются только из выпусков этого репозитория на GitHub. У файлов выпуска есть аттестация
  происхождения: `gh attestation verify <файл> --repo <владелец>/<репозиторий>`.
